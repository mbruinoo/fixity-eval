## Terms for planning runs and reading results

| Code | Term | Meaning | Where |
|---|---|---|---|
| <a id="b45e01"></a>`b45e01` | base request | The request on its own, with nothing added: "Can you standardize this .tsv file?" Each wording is compared with it. | [decisions/2026-10-18-09-stage-1.md](decisions/2026-10-18-09-stage-1.md) |
| <a id="e7a1c2"></a>`e7a1c2` | tuning file (file e) | `data/met_inventory_e.tsv`: 100 Met objects the exploratory phase used to try out and choose wordings. Because wordings were chosen by looking at results on it, results on it can't confirm anything. Used for trials and smoke tests only. | [data/README.md](data/README.md) |
| <a id="c0f1e2"></a>`c0f1e2` | exploratory / confirmatory | An exploratory run looks around and can suggest ideas; a confirmatory run tests an idea stated in advance (in a pre-registration), on data not used to form it, so its result can count as evidence. | [SPEC.md](SPEC.md) |
| <a id="a7b8c9"></a>`a7b8c9` | sessions per wording | How many separate sessions are given the same request. Sessions vary a lot (the same request can be typed out in one session and done with code in the next), so one session per wording says little; differences show only across many. | [decisions/2026-10-18-09-stage-1.md](decisions/2026-10-18-09-stage-1.md) |
| <a id="c4ec51"></a>`c4ec51` | real checksum of the upload | A checksum (a short fingerprint of a file's exact contents, e.g. SHA-256) of the uploaded file that a tool in the session actually computed, checked against the file by our scripts. One of the two main measures, with the error rate. | [scripts/eval_fixity.py](scripts/eval_fixity.py) |
| <a id="f1a9e4"></a>`f1a9e4` | per-row checksum (row fingerprint) | A checksum of a single row (record) rather than the whole file. Unlike a whole-file checksum, it can be stored inside the file itself, and it still shows which records changed after the rows are sorted or the file is converted, as long as the recipe (which columns, joined how, in which encoding) is stated. | [analysis/checksum_audit_exploratory.md](analysis/checksum_audit_exploratory.md) |
| <a id="5a1e70"></a>`5a1e70` | power | The chance that a study of a given size detects a difference that really exists. 80% power means that, if the wording really helps by the amount assumed, 8 runs of the study in 10 would show it clearly; the other 2 would miss it by chance. More sessions give more power. | this glossary |
| <a id="51e7a2"></a>`51e7a2` | significance level | How strict the test is: the chance we accept of "finding" a difference that isn't there, by luck alone. 5% is common; with two main measures we use 2.5% for each, so the overall chance stays near 5%. | this glossary |
| <a id="3e5a17"></a>`3e5a17` | simulation from past sessions | A way to estimate power: draw sessions at random, many thousands of times, from the results of a similar earlier run (here spike-32, on file e), and count how often a study of a given size would detect the difference. It assumes the new file behaves like the old one, which is why we also try a more pessimistic version. | this glossary |
| <a id="c057a1"></a>`c057a1` | cost guard | A spending limit written into each run's settings; the runner stops before any call that could exceed it. Only the repo author raises one. | [scripts/run_api.py](scripts/run_api.py) |
| <a id="5e0e7e"></a>`5e0e7e` | smoke test | A run of one or a few sessions to check that a setup or wording works as intended before spending more. Exploratory; never used as evidence. | [experiments/smoke-2026-10-18-row-hints/README.md](experiments/smoke-2026-10-18-row-hints/README.md) |
