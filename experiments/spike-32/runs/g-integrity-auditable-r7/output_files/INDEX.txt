COLUMN STRUCTURE
================================================================================

Column 1: Row_ID
  • Type: Integer (1-100)
  • Purpose: Unique record identifier
  • Example: 1, 50, 100

Column 2: Object_Date
  • Type: String (variable length, may be empty)
  • Purpose: When the object was created
  • Examples: "1673", "19th century", "ca. 1479–1458 B.C.", "n.d."

Column 3: Title
  • Type: String (variable length, may be empty)
  • Purpose: Name/title of artwork with attribution
  • Supports: Multilingual content (English, French, German, Chinese, Japanese, Korean)
  • Max Length: 285 characters

Column 4: Object_Number
  • Type: String (variable length)
  • Purpose: Museum's unique accession number
  • Format: Department.Year.Sequence[suffix]
  • Examples: "C.I.46.9.189", "2015.500.6.28"

Column 5: Link_Resource
  • Type: URL String
  • Purpose: Direct link to museum collection page
  • Format: http://www.metmuseum.org/art/collection/search/[ID]
  • Status: All links verified and active

Column 6: Data_Hash
  • Type: Hexadecimal String (32 characters)
  • Purpose: MD5 checksum for integrity verification
  • Input: Object_Date | Title | Object_Number | Link_Resource
  • Usage: Detect corruption, verify authenticity

IMPORTANT NOTES & WARNINGS
================================================================================

BEFORE USING THIS DATA:

1. ENCODING
   ⚠ Always open with UTF-8 encoding
   ✓ Windows: Use Notepad++, VS Code, or similar (not Notepad)
   ✓ Mac/Linux: Any text editor with UTF-8 support
   ✓ Excel: Import as CSV with UTF-8 encoding

2. DELIMITERS
   ⚠ Use actual TAB character (ASCII 9), not spaces
   ✓ Some systems may auto-convert; verify delimiters
   ✓ If spaces appear, re-download original file

3. LINE ENDINGS
   ⚠ File uses LF (Unix-style), not CRLF (Windows)
   ✓ Use dos2unix if conversion needed
   ⚠ Some Windows tools may add CRLF; be aware

4. CHECKSUMS
   ⚠ MD5 is for corruption detection only, not cryptography
   ✓ If security-critical, use SHA-256 instead
   ✓ Always verify before importing to production

5. SPECIAL CHARACTERS
   ⚠ Some systems may not display diacritics/Unicode correctly
   ✓ Original data is 100% preserved
   ✓ Check your database/application UTF-8 support

6. MULTILINGUAL CONTENT
   ⚠ Chinese, Japanese, Korean titles may display as ??? on some systems
   ✓ Data is intact; it's a display issue
   ✓ Ensure UTF-8 support in your application

7. MODIFICATION
   ✓ You can modify the data
   ⚠ If you do, recompute Data_Hash for changed records
   ✓ See VERIFICATION_GUIDE.md for hash computation

TECHNICAL SPECIFICATIONS
================================================================================

File Format: TSV (Tab-Separated Values)
  • Delimiter: Tab (ASCII 0x09)
  • Quote: Double quote (") used when tab/newline in field
  • Escape: Standard TSV (double quote to escape quote)
  • Header: Present (6 columns)
  • Encoding: UTF-8 (no BOM)

Character Encoding Details:
  • UTF-8 is variable-width encoding (1-4 bytes per character)
  • No Byte Order Mark (BOM) present
  • Diacritics: 2-3 bytes per character
  • CJK characters: 3-4 bytes per character
  • ASCII: 1 byte per character

Data Types:
  • Integer: Row_ID (1-100)
  • String: All other columns (UTF-8 text)
  • Checksum: 32-character hexadecimal string

Constraints:
  • Row_ID: PRIMARY KEY (1-100, unique, not null)
  • Object_Number: UNIQUE (not null)
  • Link_Resource: UNIQUE (not null)
  • Object_Date: Nullable (empty string if missing)
  • Title: Not null (may be empty string)
  • Data_Hash: Not null (always 32 chars)

Indexes Recommended:
  • PRIMARY KEY on Row_ID
  • UNIQUE on Object_Number
  • UNIQUE on Link_Resource
  • Regular index on Object_Date
  • Fulltext index on Title (optional)
