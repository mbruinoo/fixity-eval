================================================================================
FILE INTERDEPENDENCIES
================================================================================

standardize.sh (Main Orchestrator)
├─ Requires: standardize_tsv.py
├─ Calls: standardize_tsv.py
├─ Generates: checksums.json, verification.txt
└─ Optional: validate_tsv.py, verify_checksums.sh

standardize_tsv.py (Core Engine)
├─ Reads: Input TSV file
├─ Produces: Output TSV file
└─ Generates: checksums.json

validate_tsv.py (Quality Assurance)
├─ Reads: Source and Output TSV files
├─ Requires: No dependencies
└─ Produces: Validation report (stdout)

verify_checksums.sh (Integrity Check)
├─ Reads: checksums.json
├─ Requires: sha256sum, jq (optional)
├─ Verifies: Source and Output files
└─ Generates: Verification report


================================================================================
ERROR DETECTION & RECOVERY
================================================================================

PROBLEM DETECTION
─────────────────
validate_tsv.py → Detects:
  ✗ Column count inconsistency
  ✗ Row count mismatch
  ✗ Missing data
  ✗ Sorting errors

verify_checksums.sh → Detects:
  ✗ File corruption
  ✗ Unauthorized modification
  ✗ File replacement
  ✗ Bit rot

RECOVERY OPTIONS
────────────────
1. Check validation report
2. Run verify_checksums.sh
3. Review checksums.json
4. Re-standardize if needed
5. Restore from backup if corrupted

================================================================================
SECURITY & INTEGRITY GUARANTEES
================================================================================

What SHA-256 Protects Against
  ✓ Accidental bit corruption
  ✓ File transfer errors
  ✓ Storage media degradation
  ✓ Unintentional modifications
  ✓ Detection of file tampering

What SHA-256 Does NOT Protect Against
  ✗ Cryptographic attacks (theoretical, not practical)
  ✗ Protection against intentional replacement of both file AND checksum

Integrity Best Practices
  1. Keep checksums.json with files
  2. Store copies in separate locations
  3. Verify periodically
  4. Use version control (Git, etc.)
  5. Maintain audit logs
