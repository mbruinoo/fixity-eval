WHAT GETS STANDARDIZED
================================================================================

BEFORE                      →  AFTER
──────────────────────────      ─────────────────────────
Mixed encoding              →  UTF-8 throughout
CRLF or LF line endings     →  Unix LF only
Headers with spaces         →  Normalized
Extra whitespace in values  →  Trimmed
Inconsistent delimiters     →  Consistent tabs
Unchecked data quality      →  Issues identified

CHECKSUM VERIFICATION
================================================================================

What is a checksum?
  → A unique "fingerprint" of a file
  → Detects any changes or corruption
  → Uses math, not data content

When to verify:
  → After file transfer
  → Before important use
  → Periodically for long-term preservation
  → Anytime you suspect corruption

How to verify:
  $ python3 verify_integrity.py \
      met_inventory_standardized.tsv \
      met_inventory_manifest.json

Checksums used:
  → MD5:    32-character fingerprint (legacy, quick)
  → SHA256: 64-character fingerprint (secure, standard)

INTERPRETING RESULTS
================================================================================

✓ Verification PASSED
  All checks successful. File integrity confirmed. Safe to use.

✗ Verification FAILED
  Checksums don't match. File may be corrupted. Investigate before use.

COMMON SCENARIOS
================================================================================

Q: I haven't run it yet
   A: Type: ./run_standardization.sh

Q: Why different file sizes?
   A: Normal. Standardization may adjust whitespace and formatting.
      Checksums verify content is correct.

Q: Can I edit the standardized file?
   A: Yes, but checksums will change. Document changes in a new audit log.

Q: How do I know it worked?
   A: Run: python3 verify_integrity.py
      Look for: "✓ VERIFICATION PASSED"

Q: What if verification fails?
   A: Don't use file. Check for corruption. Re-run standardization.

Q: How often should I verify?
   A: Annually for important files. Anytime before critical use.

MANIFEST JSON
================================================================================

Key fields:
  - timestamp: When standardization happened
  - source_file.checksums: Original file fingerprints
  - output_file.checksums: New file fingerprints
  - statistics.total_rows: Number of records
  - statistics.issues_found: Data quality problems
  - issues: List of problems identified

To read manifest:
  $ python3 -m json.tool met_inventory_manifest.json

TROUBLESHOOTING QUICK GUIDE
================================================================================

Problem: "Command not found" or permission denied
Fix:     $ chmod +x standardize_tsv.py run_standardization.sh verify_integrity.py

Problem: Python version error
Fix:     $ python3 --version  (need 3.x)

Problem: File not found errors
Fix:     $ ls -la /mnt/user-data/uploads/met_inventory.tsv

Problem: Encoding errors on input
Fix:     File should be readable. Script handles UTF-8, Latin-1, etc.

Problem: Verification checksum mismatch
Fix:     File may be corrupted. Check manifest not modified. Re-standardize.

Problem: Output files not created
Fix:     Check write permissions. Check disk space. Review audit log.

CHECKSUM VALUES
================================================================================

To find checksums:

In manifest:
  $ python3 -c "import json; m = json.load(open('met_inventory_manifest.json')); print(m['output_file']['checksums'])"

Compute fresh:
  $ md5sum met_inventory_standardized.tsv
  $ sha256sum met_inventory_standardized.tsv

Should match manifest values exactly.
