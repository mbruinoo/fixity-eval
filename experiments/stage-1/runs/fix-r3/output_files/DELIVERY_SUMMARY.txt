FIXITY VERIFICATION APPROACH
================================================================================

Multiple layers of integrity checking are provided:

LAYER 1: CRYPTOGRAPHIC CHECKSUMS
- SHA256: Strong cryptographic hash (256-bit)
  Used for: Long-term file integrity verification, digital preservation
  Format:  64 hexadecimal characters
  
- MD5: Legacy hash algorithm (128-bit)  
  Used for: Compatibility with older systems, quick verification
  Format:  32 hexadecimal characters

LAYER 2: AUTOMATED VERIFICATION SCRIPTS
- verify_integrity.sh: Checks current file against stored checksums
- Returns pass/fail status for automated workflows
- Compares both SHA256 and MD5 hashes

LAYER 3: REPRODUCIBILITY
- Original scripts provided to re-run standardization
- Same input will generate identical checksums
- Ensures standardization process is auditable

LAYER 4: DOCUMENTATION
- Complete record of all transformations
- Before/after file statistics
- Modification timestamps
- Processing methodology

TROUBLESHOOTING
================================================================================

Issue: "Checksum verification failed"
Solution: 
  - File may have been modified or corrupted
  - Download fresh copy from source
  - Re-run process_and_verify.sh

Issue: "Cannot open file in spreadsheet program"
Solution:
  - Ensure you have a text editor or CSV-capable program
  - TSV files are plain text, should open in any text editor
  - For Excel: Use "Text to Columns" with Tab delimiter

Issue: "Special characters appear garbled"
Solution:
  - Ensure your program is set to UTF-8 encoding
  - Check file encoding settings in your editor
  - Use: file -i met_inventory_standardized.tsv (should show UTF-8)

Issue: "Scripts won't run"
Solution:
  - Make scripts executable: chmod +x *.sh
  - Ensure Python 3 is installed: python3 --version
  - Check current directory: pwd
  - Run from directory containing the scripts
