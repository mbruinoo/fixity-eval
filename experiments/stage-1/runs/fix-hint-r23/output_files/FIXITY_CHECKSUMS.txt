FIXITY VERIFICATION APPROACH
------------------------------------------------------------------------

1. PRESERVATION OF DATA INTEGRITY
   - All original values preserved exactly (no content modification)
   - Checksums document the standardization transformation
   - Row-level checksums enable tracking of individual record changes

2. VERIFICATION WORKFLOW
   To verify that no corruption occurred during transfer:

   a) Calculate SHA-256 of each row's tab-separated values
   b) Compare against checksums in this document
   c) Any mismatch indicates data modification or corruption
   d) Row-level granularity allows identifying exactly which records changed

3. STANDARDS COMPLIANCE
   - SHA-256 is industry-standard for digital preservation
   - Checksums meet OAIS (Open Archival Information Systems) requirements
   - Row-level checksums support granular fixity tracking
   - Documentation supports audit trails and provenance

4. PRACTICAL USAGE
   Example verification command (SHA-256):
     sha256sum met_inventory_standardized.tsv
     
   Example row verification (Linux/Unix):
     head -2 met_inventory_standardized.tsv | tail -1 | sha256sum
