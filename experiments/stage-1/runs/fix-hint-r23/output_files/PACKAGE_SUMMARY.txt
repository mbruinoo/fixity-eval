FIXITY PROTECTION EXPLAINED
================================================================================

WHAT IS FIXITY?

Fixity = The logical and physical integrity of digital objects maintained 
from creation through indefinite preservation. It protects against:

  • File corruption during transfer
  • Accidental modification
  • Storage degradation
  • Unauthorized changes
  • Data migration errors

THREE-LEVEL CHECKSUMS:

1. FILE-LEVEL CHECKSUM
   └─ Detects ANY change to entire file
   └─ Use: Verify integrity after download/transfer
   └─ Example: sha256sum met_inventory_standardized.tsv
   └─ Value: e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9

2. ROW-LEVEL CHECKSUMS (All 86 Records)
   └─ Identifies which records changed (if any)
   └─ Use: Granular integrity tracking
   └─ Example: SHA-256 of tab-separated values per row
   └─ Benefit: Can isolate problems to specific records

3. HEADER CHECKSUM
   └─ Verifies column structure unchanged
   └─ Use: Quick structural validation
   └─ Example: Verify headers are "object_date\ttitle\t..."
   └─ Value: 1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e

WHY SHA-256?

  ✓ Cryptographically secure (NIST FIPS 180-4 standard)
  ✓ Industry standard for digital preservation
  ✓ Extremely collision-resistant (computationally infeasible to forge)
  ✓ Widely supported (all operating systems and tools)
  ✓ Deterministic (same input → same output always)
  ✓ One-way (can't recover data from hash)
  ✓ Length: 64 hexadecimal characters

TROUBLESHOOTING
================================================================================

PROBLEM: Checksum doesn't match FIXITY_CHECKSUMS.txt

CAUSES & SOLUTIONS:

  1. File was edited
     └─ Solution: Don't edit with Excel (may change encoding)
     └─ Use: Text editor only if needed
     └─ Preferred: Use as-is without editing

  2. Line endings converted (LF ↔ CRLF)
     └─ Solution: Run verification script (handles both)
     └─ Or: Convert line endings back to original

  3. UTF-8 encoding changed
     └─ Check: file -b met_inventory_standardized.tsv
     └─ Should show: "text/plain; charset=utf-8"
     └─ Solution: Re-encode to UTF-8 if different

  4. File incomplete
     └─ Check: File size should be approximately XX KB
     └─ Solution: Re-download the file

  5. Wrong checksum value
     └─ Verify: You copied correct value from FIXITY_CHECKSUMS.txt
     └─ Check: No extra spaces in the checksum value
     └─ Solution: Copy-paste directly from document

SOLUTION: Run diagnostic script

  python3 verify_met_inventory.py met_inventory_standardized.tsv
  
  This will identify the exact problem and suggest fixes.
