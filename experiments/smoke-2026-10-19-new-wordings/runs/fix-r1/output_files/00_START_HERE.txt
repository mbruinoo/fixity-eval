================================================================================
FIXITY PRESERVATION EXPLAINED
================================================================================

FIXITY = Digital objects remain unchanged

YOUR CHECKSUMS:
  SHA-256 Algorithm: Industry-standard cryptographic hash
  Output: 64-character hexadecimal fingerprint
  Purpose: Detect ANY change, however small
  Security: NIST FIPS 180-4 approved

HOW IT WORKS:
  1. File → SHA-256 algorithm → Hash value (64 characters)
  2. Same file always → Same hash (deterministic)
  3. Any modification → Completely different hash (sensitive)
  4. Two files matching = Verified integrity ✓

VERIFICATION:
  Run: sha256sum met_inventory_standardized.tsv
  Compare to: Value in CHECKSUMS.txt or fixity_report.json
  Match = File integrity verified ✓
  Different = File has been modified

LONG-TERM USE:
  Store checksums in separate location from files
  Verify quarterly to detect corruption early
  Maintain multiple backup copies
  Annual comprehensive audit
